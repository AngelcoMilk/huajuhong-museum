# 课题与范围

## 课题

- **名称**：化州橘红博览馆数字化展示系统
- **载体**：Web 网站，电脑和手机都能访问
- **定位**：线下博览馆的线上补充和自助浏览渠道，不替代线下宣传和人工讲解

## 课题描述的两个版本

| | 版本 A | 版本 B（当前采用） |
|---|---|---|
| 技术路线 | 依托现有文化云平台进行二次开发 | 以 Web 网站为载体，从零搭建 |
| 资料来源 | 整合橘红产业文化与非遗工艺资源 | 以公开资料为基础整理 |
| 定位 | 以数字化展示替代传统线下宣传与人工讲解 | 线上补充，不替代线下宣传与人工讲解 |

两个版本要做的功能是一样的。本项目按版本 B 设计。

> **待确认**：是否必须在某个现有的"文化云平台"上二次开发。如果必须，技术栈要重新定。

## 必做功能

课题里明确写了下面四项。它们一般会写进任务书和开题报告，最后要能一项项演示出来：

1. 展品图文与视频的在线浏览
2. 分类检索
3. 移动端自适应展示
4. 后台内容管理：维护展品信息和展示内容

## 亮点

1. **古法加工 3D 动画**（本项目的主体展项）
   - 把《中国药典》1963 年版一部「橘红」条那套工艺整段演出来：烫果、割皮去瓤、晒、润透对折压平、复焙，一直到十片一扎。
   - **四条产线**：七爪（割七刀、整片对折）、大五爪（割五刀、瓣尖内折）、压果片（整果压扁、复焙、切药刀切片）、橘红胎（小果整只烘）。四条线共用同一个院子、同一口灶、同一口锅，前段的摘果、称果、烫果是同一份代码，只换参数。
   - **全部程序化生成**：不导入任何外部 3D 模型，不用贴图，连声音都用 Web Audio 实时合成，断网可跑。
   - **呈现方式**：自动演示，观众可以拖动进度、选章节、开关声音；不做玩家操作、不设输赢。
2. **成品 3D 展台**：七爪、大五爪、压果片、橘红胎等成品，可以 360° 旋转查看。
3. **AI 讲解员**：内嵌在网页里的 Agent。它根据知识库回答问题，还能带参观者去看对应的展品和动画章节。

**优先级**：必做功能 → 古法加工 3D 动画 → 成品 3D 展台 → AI 讲解员。亮点没做完问题不大，必做项缺了才麻烦。

> 2026-10-21 曾定过"内嵌 2D 像素小游戏"的路线（果园、院子横版像素 + 视觉小说对话），2026-10-22 用户决定取消：游戏化的互动环节全部改为 3D 动画演示。相关文档 05、08–13 已退役。

## 内容策略

- **系统是成果，内容是演示数据。** 我们没有博览馆的授权，内容根据公开资料整理。后台内容管理的意义，就在于内容随时可以替换。
- **够演示就行。** 大约五六个分类，每类五到八件展品，再配几段视频。这样分类、搜索、分页、视频播放都有数据可以演示。
- **不能出错。** 文字从调研报告里摘，并对照报告附录 F 避开常见的错误说法，比如"化橘红就是橘子皮""李时珍《本草纲目》记载化橘红"。涉及功效的内容只用药典原文。
- **不冒充官方。** 不使用实体馆或官网的标志。网上的图片、视频要注明出处。页脚写明"本站为毕业设计作品，内容整理自公开资料，非官方网站"。
- 课题里的"化州橘红博览馆"，按一个以实体馆为原型的虚拟馆来做。实体馆的正式名称是"中国化橘红博览馆"，位于化州市新安镇。

## 实体馆参考

根据金羊网 2026-05-01 的报道，中国化橘红博览馆的参观顺序是：序厅 → 历史展厅 → 非遗展区（七爪化橘红和古法工序）→ 橘香屋 → 品鉴区 → 文创体验区。报道没有提到任何线上或扫码功能，讲解由现场讲解员负责。

- 线上展厅的分类可以参考这个顺序，不必照搬。
- 实体馆缺少线上渠道，这一点可以写进研究背景。
- 闻香、品茶、封坛这些体验没法搬到线上，这是"补充、不替代"的论据。

## 论文注意事项

- 古法加工 3D 动画是自己写的程序：Geometry、材质、光照、音效全部由代码生成，论文里要写清实现方式与工作量。
- 展厅里现代机械的交互图由 anatomy 技能配合 Claude Code 生成。论文里要写明用到的工具和它们的许可证。现在不少学校要求披露论文中 AIGC 的使用情况。
- 借鉴的开源代码保留原许可证和署名，并在论文里注明。
