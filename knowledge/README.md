# knowledge —— 本地 LLM Wiki

一套给**任何 LLM / Agent** 用的离线知识库：报告和原文被拆成互相链接的短页，模型从目录进来，命中一页就走，不必读别的文章。

> **第一次使用，先读 [`START.md`](START.md)（一屏定位）；要动手整理再看 [`AGENTS.md`](AGENTS.md)。** 那里是给模型的读取与维护规范；这一页是给人看的。

---

## 结构

```
knowledge/
├── START.md       ← ★ 极简入口（一屏定位，日常先读这个）
├── AGENTS.md      ← 完整的读取与维护规范
├── index.md       ← 分类目录 + 任务路由
├── log.md         ← 变更记录（追加，不改历史）
├── raw/           ← 原文，只进不改
│   ├── README.md                 资料登记表 + 待补清单（部分已由官网镜像补齐）
│   ├── 2026-10-19-化橘红完整调研报告.md
│   └── 化橘红官网镜像/           479 篇官网文章 + 索引 + 资源清单
└── wiki/          ← 17 个主题页，页间互链
    ├── 是什么.md            历史时间轴.md        工艺流程.md
    ├── 机器清单.md          质量标准.md          产业数据.md
    ├── 易错说法.md          典故与文艺作品.md    产品图谱.md
    ├── 功效与用法（官网口径）.md  园区与产业载体.md  近年产业动态.md
    ├── 官网镜像导览.md      技术选型-3D与流程图.md
    └── HDRI与环境光.md      3D素材与许可.md      知识库方法论.md
```

## 三条规矩

| 规矩 | 理由 |
|---|---|
| `raw/` 只进不改 | 原文是证据；改写、提炼一律进 `wiki/` |
| `wiki/` 一页一主题 | 一页 1–3 千字，模型读一页成本低，引用也准 |
| 新增页面必须登记 | 在 `index.md` 加一行、在 `log.md` 加一条，否则等于没加 |

## 模型怎么用

```
① 读 START.md（一屏目录）→ ② 读 index.md（按需查分类）→ ③ 只读命中的 wiki 页
→ ④ 要原文时按页首 source 回 raw 对应章节 → ⑤ 找不到就看 raw/README.md 待补清单
```

**不要**一次读整个 `raw/`：调研报告两万字、官网文章近 61 万字，会挤掉真正要用的上下文；按目录、索引和 `source:` 定点读。

## 人怎么用

- **写文案**：`wiki/是什么.md` ＋ `wiki/易错说法.md` 过一遍
- **做动画**：`wiki/机器清单.md` §一（五类独有机器 + 专利号 + 可交互点）
- **查数据**：`wiki/产业数据.md`、`wiki/质量标准.md`
- **补资料**：`raw/README.md` 的待补清单，按优先级补，补完登一行

## 和其他方案的关系

- **不用向量库 / Docker / embedding**：479 篇官网文章 + 17 个主题页；文章用「年份目录 + 文章索引.csv + grep」定位，wiki 用目录精确命中整页，可复现、可引用
- **不用 NotebookLM 式 RAG**：那是每次重新检索；这里是编译一次、持续维护
- **给 AI 讲解员（pi）的两个工具**：读 `index.md`、按路径读 `wiki/*.md`（白名单校验，只读）
