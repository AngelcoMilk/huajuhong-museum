# 3D 素材与许可

## 结论先行

Asset Store 的标准 EULA 将使用权绑定在“以 Unity 制作的产品”上，导出到其他引擎属于超出该许可范围；技术上还会丢失材质与动画。CC0 的 glTF 库可直接下载 `.glb`，无需转换。

---

## 能用：CC0 / 直接给 glb

| 库 | 地址 | 内容 | 许可 |
|---|---|---|---|
| **Poly Pizza** | poly.pizza | 聚合库，**一键下 .glb**，可按 CC0 筛 | CC0 / CC-BY 混合 |
| **Poly Haven** | polyhaven.com | **HDRI + PBR 材质 + 少量模型**，质量顶级 | 全 CC0 |
| **Kenney** | kenney.nl/assets | 低多边形 Kit 积木件，风格统一 | 全 CC0 |
| **Quaternius** | quaternius.com | 低模资产包，量大 | 全 CC0 |
| **Khronos glTF-Sample-Assets** | github.com/KhronosGroup/glTF-Sample-Assets | 官方测试模型（★1,119，2026-10 活跃） | 混合，逐个看 |
| **three.js 自带 models** | three.js/examples/models | DamagedHelmet 等，开箱即用 | 混合 |
| **AmbientCG** | ambientcg.com | 材质/贴图 | CC0 |

> 旧的 `glTF-Sample-Models` 仓库 **2023-12 已停更**，全部迁到 `-Assets`，旧地址已停止更新。

## 能用但要署名 / 看条款

| 库 | 说明 |
|---|---|
| **Sketchfab** | 筛选：`Downloadable` + License = **CC0 / CC-BY**，格式选 **glTF**。工业设备（液压机、传送带、烘箱）有货，但多为 CC-BY（要署名），不少是 **CC-BY-NC（禁商用）** |
| **OpenGameArt** | CC0 区可用，质量参差 |
| **Smithsonian 3D** | 文物级扫描，CC0，站点有反爬（实测 403） |
| **BlenderKit** | 部分免费，每个资产许可不同 |

## 许可不覆盖 Web 引擎的来源

| 来源 | 原因 |
|---|---|
| **Unity Asset Store**（含免费区） | 标准 EULA 把使用权绑定在“用 Unity 制作的产品”上，导出到 three.js 属超范围使用 |
| **Quixel Megascans** | 许可绑定 Unreal |
| **NASA 3D** | 原地址已 404，资源迁到 science.nasa.gov，入口要重找 |

## 从 Asset Store 搬的六项损耗

| 问题 | 具体 |
|---|---|
| 许可 | 绑定 Unity 项目 |
| **材质必丢** | Unity 的 `MetallicSmoothness` 是打包贴图（R=金属度、A=光滑度），glTF 要拆成两张，得手工重做 |
| Shader 不转 | Standard / URP / HDRP 没有对应物，全部要重写 |
| 动画不转 | Animator Controller 状态机导不出，只有 AnimationClip 能勉强带走 |
| Prefab 失效 | 层级、材质引用、LOD 全丢，等于重新组装 |
| 单位错乱 | Unity 1 unit = 1 m，FBX 常是 cm，导入 Blender 要改 scale，很容易做成 100 倍大的机器 |

**搬一个模型 = 拆包 → Blender 修 → 重做材质 → 重接动画**，比直接下 glb 慢十倍。

## 合规路径：导出自己的 Unity 场景

**不是扒别人的资产，而是导出你自己的场景**：

```
Unity 场景（自建 / 有授权的资产）
  → 装 Khronos 官方 UnityGLTF 或 Unity glTFast
  → Export .glb（含材质、动画、骨骼）
  → three.js / model-viewer 载入
```

### 真要解包（技术参考，注意许可）

- `.unitypackage` 本质是 **gzip 压缩的 tar**：`tar -xzf xxx.unitypackage`
- 里面按 GUID 命名，每个目录含 `asset`（真实文件）、`pathname`（原路径）、`preview.png`
- 用 `pathname` 还原目录结构，捞出 `.fbx` + 贴图
- 拿到 `.fbx` 后：Blender 导入（**记得改 scale**）→ 重做材质 → 导出 glTF

## 本项目的素材策略

公开库里**不可能有“化橘红专用设备”**。实际方案：

| 要的东西 | 怎么来 |
|---|---|
| 液压压果机 | 通用 `hydraulic press` 低模改造，或**程序化几何** |
| 传送带/产线 | Kenney / Quaternius 的 Kit 拼装 |
| 烘房（箱体+门+风机） | **three.js 程序化生成 Box + 材质**，5 分钟 |
| 分级滚杠机 | 圆柱阵列程序化生成 |
| 七爪切瓣机构 | 圆柱 + 刀片几何体 + 旋转动画 |
| 柑橘/柚子果 | Sketchfab 搜 `pomelo` / `citrus`，或球体 + 绒毛法线 |
| 车间环境光 | Poly Haven HDRI（CC0） |
| **成品（七爪、圆果、胎）** | **实物拍照 + AI 图生 3D（混元 3D）→ GLB** |

> 这几类设备几何结构简单：程序化生成不依赖任何外部素材；找现成模型则受许可与格式限制。两条路径的差别在依赖项，不在效果上限。

## 转换管线

```bash
# 转格式 & 瘦身
npx @gltf-transform/cli optimize in.glb out.glb --compress draco --texture-compress webp
# 检查
npx @gltf-transform/cli inspect out.glb
# Blender 导出：glTF 2.0 (.glb)、+Y up ✓、Apply Modifiers ✓
```
