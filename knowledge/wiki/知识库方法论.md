# 知识库方法论

## 核心主张（要抄的就是这个）

传统 RAG：上传一堆文件，每次提问都重新检索片段、重新拼答案，**知识没有积累**。

LLM Wiki：让模型**增量构建并维护一个持久 wiki**——它读新资料、抽出要点、整合进已有页面、更新索引、标注矛盾。**知识编译一次，持续维护，不是每次重新推导。**

> 一句话：**wiki 是持久的、会复利增长的产物。** 交叉引用已经在那儿了，矛盾已经标出来了。

---

## 三层架构

| 层 | 是什么 | 谁写 |
|---|---|---|
| **raw** | 原始资料（文章、论文、图片、数据） | 人放，**不可变**，是 source of truth |
| **wiki** | LLM 生成的 markdown（摘要、实体页、概念页、对比、综述） | **LLM 写**，人只读 |
| **schema** | 约定文件（AGENTS.md / CLAUDE.md）：结构、规范、工作流 | 人和 LLM 共同演进 |

**schema 是关键**：它让模型成为“守规矩的 wiki 维护者”，而不是普通聊天机器人。

## 三个操作

| 操作 | 做什么 |
|---|---|
| **Ingest** | 丢一份新资料 → 读它 → 写摘要页 → **更新 index** → 更新相关实体页 → 追加 log。一份资料可能触及 10–15 页 |
| **Query** | 提问 → 找相关页 → 读页 → 带引用回答。**好答案要回写成新页面**，别让它消失在聊天记录里 |
| **Lint** | 定期体检：页面间矛盾、过期结论、无入链的孤儿页、提了但没自己页的概念、缺交叉引用、可补的空白 |

## 两个特殊文件

- **`index.md`**：内容目录，**模型回答前先读它**找相关页，再深入。作者实测：**约 100 个来源、数百页面规模内效果好，不需要 embedding**
- **`log.md`**：追加式时序记录，格式统一到可 `grep "^## \[" log.md | tail -5`

## 约定

- `[[wikilink]]` 语法交叉引用
- 每个 wiki 页有 **YAML frontmatter**
- 与 **Obsidian 兼容**（wiki 目录可直接当 vault 打开）

## 与本项目形态的四点差异

| 理由 | 具体 |
|---|---|
| **规模不匹配** | 本库是 2 份报告 + **479 篇官网文章（带 CSV 索引）** + 17 个主题页；文章靠年份目录 + `文章索引.csv` + grep 定位，wiki 靠 `index.md` 命中。索引式定位在 ~100 个「来源类别」规模内仍有效；上 LanceDB + 图谱是过度工程 |
| **部署形态不匹配** | 它的 MCP Server **只是桌面应用的转发器**，所有工具都调 `127.0.0.1:19828`，要求应用正在运行。本项目讲解员是**服务端 pi Agent**，接不了 |
| **许可风险** | GPL-3.0。当工具生成 markdown 没问题；把代码嵌进 Web 毕设 → 毕设要按 GPL 兼容开源，学校大概率不接受 |

## 适用规模

1. raw 超过 ~50 份、且每周新增 → Ingest 自动化才有价值（本库 2026-10-21 已入库 479 篇官网文章，但有固定年份目录 + 文章索引，且不每周新增，先加索引与 grep 即可）
2. 论文需要“知识图谱”这一节 → 它的图谱 + 社区检测 + 知识空白检测，截图很好看
3. 想自动标注矛盾 → Lint 能发现“报告说 A、官网说 B”

**不引入代码的用法**：把它当离线分析工具跑一遍 → 导出图谱截图、Lint 报告 → 写进论文 → **代码不进项目**（规避 GPL 传染）。

## 本库就是按这套做的

| 方法论要求 | 本库对应 |
|---|---|
| raw / wiki / schema 三层 | `raw/` / `wiki/` / `AGENTS.md` |
| index.md 作为导航入口 | `index.md` + 极简入口 `START.md` |
| log.md 时序记录 | `log.md` |
| 页间交叉引用 | 每页底部 `## 相关` |
| frontmatter | `title` / `source` / `updated` |
| 回答带引用 | `source:` 字段指向 raw 章节 |
| Lint | 定期检查断链、孤立页、过期结论（见 AGENTS.md） |

**唯一没做的**：向量检索与知识图谱——因为规模不需要（理由见上）。

## 可选的检索增强（将来）

当 wiki 页超过 50 个，可以加一个本地 markdown 搜索（如 `qmd`：本地 BM25 + 向量 + LLM 重排，有 CLI 和 MCP 两种接法）。现在加是过度工程。

## 四个已知问题

| 问题 | 说明 | 处理 |
|---|---|---|
| **wiki 会漂移** | Ingest 时模型会改写页面、标矛盾，演示前跑一次可能改乱文案 | raw 冻结；wiki 人审后入库；演示前打 tag |
| **演示时只读** | 讲解员若能写 wiki，一次幻觉就污染知识库 | 工具只给只读 |
| **index 会膨胀** | 超过 ~80 行，读它就浪费上下文 | 拆成一级 index + 分册 |
| **必须带 source** | 否则无法注明出处 | frontmatter 强制 `source:` |
